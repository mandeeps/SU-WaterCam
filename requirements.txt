# Node venv for ticktalk (runrtm.py / ticktalk_main.py) and lora_daemon.service.
#
# 1. System packages. These come from apt, not pip (picamera2 and the camera
#    stack are only packaged for Debian), and the venv must see them:
#
#      sudo apt install python3-picamera2 python3-numpy \
#          python3-pandas python3-scipy python3-gpiozero python3-piexif \
#          python3-pil python3-pytz python3-rasterio python3-gdal \
#          python3-pygraphviz python3-venv python3-wheel python3-dev \
#          exempi libgpiod-dev gpsd rsync
#      python3 -m venv --system-site-packages /home/pi/SU-WaterCam/venv
#
#    exempi is the library python-xmp-toolkit (libxmp) loads; python3-dev is
#    needed to build RPi.GPIO, which ships only as source; gpsd serves the
#    GPS that py-gpsd2 talks to; rsync is how captures are copied off a node.
#
#    Verified on ufo-01-01-005 and ufo-01-01-006 (Debian 13 trixie), where these
#    provide numpy, pandas, scipy, picamera2, gpiozero, piexif, PIL, pytz,
#    rasterio and osgeo to the venv.
#
# 2. The pip packages below, into that venv:
#
#      /home/pi/SU-WaterCam/venv/bin/pip install -r requirements.txt
#      /home/pi/SU-WaterCam/venv/bin/pip install --ignore-installed six==1.17.0
#
#    The second line puts six in the venv itself. With --system-site-packages pip
#    counts apt's python3-six as installed and skips it, and apt removes
#    python3-six along with python3-opencv (purged per the guide, 1.3.2): then
#    astunparse fails to import and ticktalk doesn't start (010, 2026-10-15).
#    Check: venv/bin/python -c "import six; print(six.__file__)" is under venv/.
#
# OpenCV (cv2) comes from pip's opencv-python-headless, not apt's python3-opencv:
# apt's package pulls in about 450 MB the nodes never use (VTK, LLVM 17, AMD's GPU
# runtime, OpenMPI, Tesseract). Compared on 005 and 006 (2026-10-12) with the same
# cached transform: identical masks, and identical images apart from band 4 on 006
# (17% of pixels off by at most 2/255). It needs numpy>=2, which apt's python3-numpy
# provides, so pip installs no second numpy. Headless means no windows:
# tools/camera_calibration.py's interactive capture is a workstation tool.
#
# segformer_daemon.service runs in this venv too. It needs onnxruntime (below),
# cv2, rasterio, numpy and PIL. Tested on ufo-01-01-005 against the 5band conda
# env: identical fp32 masks, about 10% faster. The conda env
# (segformer_5band/5band_environment.yml) is now only for the legacy
# segment_tiff_5band.py fallback in ticktalk_main.py and for model export.
